# 文档归属与维护

## 适用范围

修改 `AGENTS.md`、`docs/agent/`、项目 README、业务文档、契约注释或 Go doc 时读取。

## 单一来源

| 内容 | 权威位置 |
| --- | --- |
| Agent 每次都要遵守的少量行为 | 根目录 `AGENTS.md` |
| 跨模块且不易从源码看出的工程契约 | `docs/agent/standards/` |
| 某个业务或集成领域的稳定不变量 | `docs/agent/domains/` |
| 任务触发词到知识文档的映射 | `docs/agent/README.md` |
| 项目入口、开发、部署和完整业务流程 | `README.md` 与 `docs/` 的业务目录 |
| 字段、方法、校验和事件 schema | `.proto`、`.api`、typed 协议源码与 Go doc |
| 当前依赖版本、脚本和目录清单 | `go.mod`、脚本与文件系统 |

一次性方案、排障记录和调研材料保留在产生它们的任务或研究文档中。只有结论已经稳定、会影响未来代码正确性且无法从事实来源直接得出时，才提炼进 Agent 知识库，并链接原始证据。

## 写作标准

- 开头写清触发条件，使 Agent 能判断何时需要读取。
- 只记录稳定契约、非直观原因、失败边界和可执行验证。
- 一个含义只有一个权威位置；其他文档使用链接，不复制正文。
- 按任务分支拆文档，使一次修改只加载相关内容。
- 环境可以低成本查询的内容直接指向文件或命令，不维护文字缓存。
- 规则变化时同步入口指针；无效规则直接删除，不保留兼容占位文档。

## 完成标准

- 每条新增规则都有明确触发条件，并能指出当前源码、测试、契约或配置证据。
- 所有相对 Markdown 链接均能解析，入口没有指向已删除文件。
- 文档不包含真实凭据、内网地址、个人绝对路径或未替换占位符。
- `git diff --check` 通过，文档改动与实际行为一致。
