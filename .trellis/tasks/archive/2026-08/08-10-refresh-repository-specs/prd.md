# Refresh Repository Trellis Specs

## Goal

基于当前 `zero-service` 源码、测试、生成脚本和项目文档，审计并增量刷新 `.trellis/spec/`，确保未来开发代理读取到的是当前仓库真实、可执行且有证据支撑的编码契约。

## Scope

- 审计 `.trellis/spec/README.md`、`backend/` 和 `guides/` 的目录结构、导航和内容。
- 核对单 Go module、多服务、公共包、生成边界、数据访问、消息并发及主要领域规范与当前源码是否一致。
- 对失效路径、过时规则、遗漏的重要稳定模式和重复内容做最小必要更新。
- 检查每条重要规则是否可由源码、测试、配置、生成脚本或项目文档支撑。
- 仅修改 `.trellis/spec/` 和本任务规划/研究文件，不修改产品源码、生成产物或部署配置。

## Requirements

- 保留现有 `backend/` 与 `guides/` 分层，除非源码证据表明边界已不适用。
- 现有规范已经项目化时采用增量刷新，不用模板覆盖或为追求整齐而推倒重写。
- Spec 文件集必须围绕真实所有权边界；不为每个小包机械创建独立文件。
- 每条新增或改写的重要规则必须引用真实文件、符号、测试或项目文档。
- 删除模板占位、失效链接、空章节和不适用于当前仓库的通用建议。
- `index.md` 必须与最终文件集合和阅读路由一致。
- 不写入特定 Agent/CLI 平台才能执行的工作流说明。

## Acceptance Criteria

- [ ] `.trellis/spec/` 对当前单模块、多服务 Go 后端架构描述准确。
- [ ] backend 和 guides 的所有索引链接均指向实际存在的文件，且没有未导航的正式规范。
- [ ] 重要规则均有当前源码、测试、生成脚本、配置或项目文档依据。
- [ ] 没有 `TBD`、`TODO: fill`、`To be filled`、placeholder 或空模板章节。
- [ ] 不适用、重复或已经失效的规则被删除或合并，必要的稳定模式得到补充。
- [ ] 最终变更仅涉及 `.trellis/spec/` 与 Trellis 管理文件，不修改产品代码。
- [ ] Markdown 路径检查、占位搜索和 `git diff --check` 通过。

## Out Of Scope

- 修改产品实现以迁就 Spec。
- 重写 `README.md`、`docs/` 或外部协议文档。
- 为 Mock、历史快照、生成代码或实验目录建立独立规范。
- 验证必须依赖数据库、Redis、Kafka、MQTT Broker、设备或外部凭据的运行时行为。
