# Documentation system design

## Boundaries

- 根 `README.md`：项目入口、能力概览、最短启动路径和文档导航。
- `docs/README.md`：按读者和服务导航完整文档。
- 服务子目录：服务总览、专项指南和运维文档。
- `CONTEXT.md`：项目特有术语的规范写法、简短定义和应避免别名。
- `docs/adr/`：满足 ADR 三项门槛的决策及理由。
- `.proto`、`.api` 和 typed 源码：接口、字段、校验和事件 schema 的权威来源。

## Integration Contracts

1. 目录重排子任务先建立稳定路径；后续任务只能基于最终路径写链接。
2. 每个公共文件只有一个主要修改负责人；父任务只做最终集成验证。
3. ADR 不复制运维步骤、API 表或完整服务说明；普通文档链接到 ADR，ADR 链接回权威操作文档和证据。
4. CONTEXT 词条只回答“术语是什么”，复杂概念用一句定义和权威文档链接，不描述实现机制。
5. 所有相对资源都属于链接迁移范围，包括 Markdown 链接、HTML `img src`、图片、目录链接和源码链接。

## Compatibility

文件移动会改变公开仓库路径，因此不是严格的路径向后兼容变更。仓库内引用必须全部迁移；不创建重复兼容副本，以免形成两套文档。外部深链无法由仓库完全控制，最终交付说明应列出主要新路径。

## ADR Evidence Gate

每个候选必须同时满足：

1. 难以逆转。
2. 缺少上下文时会令人困惑。
3. 存在真实且有证据的取舍。

证据不足时，在任务结果中记录“不创建及原因”，不得补写推测。Trigger 主键迁移预计满足；antsx 与 IEC 104 三通道仍需对照源码和历史材料复核。

## Rollback

- 每个子任务保持可独立回退的文件边界。
- 若链接校验失败，先修复或回退当前子任务，不通过兼容副本掩盖问题。
- 父任务集成检查失败时，回到拥有对应文件的子任务修复。
