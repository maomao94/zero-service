### Common Transport Mechanics

`common/authctx/context.go:5-20` uses public string context keys and places Authorization first in propagation order. `common/grpcx/metadata.go:27-34` mirrors that order. Client injection copies outgoing metadata and calls `md.Set`, while extraction trusts metadata and writes context strings without validation (`common/grpcx/metadata.go:45-74`).

The repository has broad interceptor installation: examples include gateways (`gtw/internal/svc/servicecontext.go:55-63`, `aiapp/aigtw/internal/svc/servicecontext.go:65-75`), MCP server clients (`aiapp/mcpserver/internal/svc/servicecontext.go:30-35`), Trigger dynamic calls (`app/trigger/internal/invoke/grpc_invoker.go:35`), and many RPC servers listed by the `LoggerInterceptor` search. This makes propagation capability generic rather than method-scoped.

## Caveats / Not Found

- No central registry maps RPC methods or MCP tools to an intended delegation mode.
- No generic receiver-side JWT verifier was found in `common/grpcx`; individual business handlers outside searched symbols may perform authorization using request fields.
- Direct Authorization consumers found were StreamEvent logging and MCP echo logging; transport helpers remain implicit consumers because they retransmit the value.
