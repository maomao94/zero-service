# 文档思考指南

## 适用范围

修改 `.trellis/spec/`、`README.md`、`CONTRIBUTING.md`、`docs/`、`.proto`/`.api` 注释或包文档时读取。

## 内容归属

| 内容 | 位置 |
| --- | --- |
| 修改代码时必须遵守的项目契约、反模式和验证 | `.trellis/spec/` |
| 项目入口、能力概览和导航 | `README.md`、`docs/README.md` |
| 开发、部署、服务使用和完整业务流程 | `docs/` |
| 字段、方法、校验、事件 schema 的权威定义 | `.proto`、`.api`、typed 协议源码 |
| 包的导出 API 与非直观行为 | Go doc 与相邻源码 |
| 一次任务的方案、取舍和历史排障 | `.trellis/tasks/`，完成后归档 |

同一事实只保留一个权威来源。Spec 链接完整文档/源码，不复制长 API 表、配置样例、依赖版本或历史步骤。

依据：`README.md`、`docs/README.md`、`docs/development.md`、`app/trigger/trigger.proto`、`.trellis/workflow.md`。

## Spec 更新标准

- 只记录稳定、可重复应用、会影响未来修改正确性的规则。
- 每条重要规则附当前源码、测试、配置或项目文档路径；发现实现变化时先验证再更新。
- 索引只做导航，包含 Pre-Development Checklist 和 Quality Check；正文按适用范围、规则、反模式、证据、验证组织。
- 实验、Mock、历史快照、生成代码和单次排障不建立独立 Spec。
- 删除/重命名 Spec 时同步所有索引和相对链接，不保留会被注入的过时兼容文档。

## 文档规则

- `README.md` 保持入口性质，详细服务、部署和协议内容链接到 `docs/`。
- 代码行为变化后同步权威契约与真正受影响的文档，不为无关内部重构制造文档 churn。
- 示例使用占位配置并可独立理解，不包含真实凭据、内网地址或个人路径。
- 图、表和代码块只在比短文本更清晰时使用；链接使用仓库相对路径并在变更后校验。

## 反模式

- 把 Spec 写成完整 API 手册或复制源码注释。
- 用归档任务结论覆盖当前代码事实。
- 在多个文档复制依赖版本、配置默认值或协议枚举。
- 为实验组件写必读规范，让其看起来是生产契约。
- 删除正文却忘记索引和跨文档链接。

## 验证

```bash
find .trellis/spec -type f -name '*.md' | sort
git diff --check
```

另行搜索常见的中英文占位标记，并检查 Markdown 相对链接、反引号中的仓库路径、索引文件清单和敏感信息；文档变更不以 Go 测试替代内容审查。
